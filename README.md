# 정부광고 집행내역 (2022~2026.09.30 기준)

**2022~2026년 정부광고 집행내역을 검색하고, 연도·기관·매체별로 살펴보는 학습용 웹 앱**입니다. CSV 원자료를 MySQL에 저장하고 Python·FastAPI로 조회·집계한 결과를 웹브라우저에 표시합니다.

자료 파일의 기준일은 **2026년 9월 30일**입니다. 2026년 자료는 연간 확정 실적이 아닙니다. 현재 저장소에는 연도별 CSV 5개, 제목 행을 제외한 총 **1,072,033건**의 자료가 있습니다.

영문 프로젝트 이름은 `government-ad-execution-2022-2026`입니다.

**처음 설치하거나 다른 PC에서 실행하려면 → [설치·실행 안내](INSTALL.md)**

이 README는 프로젝트 소개·기능·코드 구조·데이터 해석을 설명합니다. Python·MySQL 설치와 패키지 설치 명령 등 실제 작업 절차는 위 문서에서 순서대로 안내합니다.

## 4. 파일별 역할과 수정 위치

서버·DB 연결·화면 구조·디자인·화면 동작을 파일별로 나눠, 수정할 위치를 찾기 쉽게 구성했습니다.

| 파일 | 역할 | 수정하는 경우 |
|---|---|---|
| `app.py` | 앱 시작점, 화면·API·정적 파일 연결 | 새 기능 연결 |
| `config.py` | `.env`에서 DB 설정과 프로젝트 경로 읽기 | 설정 방식 변경 |
| `database.py` | MySQL 연결 함수 | DB 연결 방식 변경 |
| `routers/ads.py` | 검색·집계 SQL, 조회 API, 진단 시간 기록 | 검색 조건·집계 변경 |
| `templates/index.html` | 제목·버튼·검색창·표 등 화면 구조 | 화면 항목 추가 |
| `static/css/dashboard.css` | 색상·크기·배치 | 디자인 변경 |
| `static/js/dashboard.js` | 검색 요청·정렬·차트·스크롤 로딩 | 화면 동작 변경 |
| `data/*.csv` | 연도별 원자료 | 자료 대조 |
| `data/load_all_years.py` | CSV를 MySQL에 추가 적재 | 데이터 적재 |
| `schema.sql` | 새 환경의 DB·표·요약 집계용 인덱스 생성 | 처음 설치 |
| `sql/add_summary_index.sql` | 기존 DB에 요약 집계용 인덱스 추가 | 기존 DB의 집계 속도 개선 |
| `.env.example` | DB 접속 정보 양식 | `.env`로 복사해 사용 |
| `requirements.txt` | 필요한 Python 패키지 목록 | 환경 준비 |
| `media_analysis/` | 두 연도 매체군 비교, 팩트시트·결과 화면·기사 초안 생성 | 비교 조건·매체 분류·기사 프롬프트 변경 |

`.env`에는 PC마다 다른 MySQL 접속 정보를 넣습니다. 실제 비밀번호를 담는 파일이므로 저장소에는 포함하지 않습니다. 웹 앱과 CSV 적재 스크립트가 같은 `.env`를 읽습니다.

`public/index.html`, `migration_constraints.sql`에는 별도 **날씨·기사 CRUD 실습** 내용이 있습니다. 현재 정부광고 앱 설치에는 사용하지 않습니다.

## 5. 로딩 개선 내용

- 상세 목록·상단 요약·선택 목록을 병렬로 요청하고, 상세 행은 전체 요약을 기다리지 않고 표시합니다.
- 첫 상세 페이지와 추가 스크롤에서는 같은 조건의 전체 건수·금액을 반복 집계하지 않습니다.
- 응답을 압축하고, 외부 차트 라이브러리는 비동기로 불러옵니다.
- 새 검색이 시작되면 이전 검색 요청을 취소하고 오래된 응답을 적용하지 않습니다.
- 새 설치용 SQL은 매체구분과 금액을 함께 담은 `idx_ad_summary_cover` 인덱스를 포함합니다.

기존 DB의 인덱스 확인·추가 방법과 진단 로그 읽기는 [설치·실행 안내 11번](INSTALL.md#11-기존-pc에서-수정본만-업데이트)에 있습니다. 앱을 실행한다고 기존 DB 구조가 자동으로 바뀌지는 않습니다.

## 6. API 목록

| 방식 | 주소 | 역할 |
|---|---|---|
| GET | `/` | 집행내역 조회 화면 |
| GET | `/api/init-data` | 전체 건수·매체 요약, 기본값으로 선택 목록도 포함 |
| GET | `/api/init-data?include_filters=false` | 첫 화면용 요약만 조회 |
| GET | `/api/filter-options` | 연도·기관·매체 선택 목록 별도 조회 |
| GET | `/api/summary?year=2025` | 해당 연도의 매체 요약·건수 |
| GET | `/api/search-ads` | 조건 검색·정렬·페이지 조회·전체 조건 합계 |

검색 조건은 `keyword`, `org_type`, `media_type`, `year`, `month`, `sort_col`, `sort_dir`, `limit`, `offset`입니다. SQL의 검색 값은 매개변수로 전달하고, 정렬 열은 허용 목록에서 선택합니다.

`limit`·`offset`은 한 번에 가져올 행의 범위입니다. 응답의 `total_filtered`·`total_sum`은 그 페이지뿐 아니라 **동일 검색 조건에 맞는 전체 행**을 집계합니다.

`include_totals=false`이면 전체 건수·금액을 다시 계산하지 않고 상세 페이지만 조회하며 합계 필드는 `null`입니다. 기존 API의 기본값은 전체 합계를 포함합니다. 첫 화면은 상단 집계 결과를 재사용하고, 추가 스크롤은 같은 검색의 합계를 재사용합니다.

API 설명 화면은 앱 실행 후 <http://127.0.0.1:8000/docs>에서 확인할 수 있습니다.

## 7. 데이터를 기사에 쓸 때 확인할 점

- 파일명의 기준일과 실제 자료 수록 기간이 일치하는지 원자료에서 확인합니다.
- `총계(VAT포함)`과 광고료·수수료의 정의·단위를 확인합니다.
- CSV와 DB의 건수·금액을 대조하고 중복 적재 여부를 확인합니다.
- 2026년 일부 기간과 다른 연도 전체를 단순 비교하지 않습니다.
- 상단 요약과 상세 검색의 집계 범위를 구분합니다.
- 화면의 억·만 단위 요약은 만 원 미만을 생략하므로, 기사에는 정확한 원 단위 합계를 대조합니다.

현재 적재 코드는 `집행년월`을 실제 광고 날짜에서 계산하지 않고 **해당 연도의 01월로 채웁니다.** 따라서 월별 집계의 근거로 쓸 수 없습니다. `집행연도`는 파일별 연도에서 채웁니다.

적재는 추가 방식입니다. 같은 CSV를 다시 넣으면 중복될 수 있고, 10,000건씩 저장을 확정하므로 도중 실패해도 앞서 저장한 자료가 남을 수 있습니다. 최초 적재와 건수 대조 절차는 설치 안내에 있습니다.

CSV만으로 광고 집행 사유·적정성·특혜 여부를 확정할 수 없습니다. 출처 문서와 추가 취재가 필요합니다. 원자료 제공기관의 링크·이용 조건은 저장소의 확인 자료가 없어 여기서 확정하지 않습니다.

## 8. 개발자용 동작 검증

설치와 패키지 준비를 마친 Windows PowerShell에서 다음 명령으로 Python 테스트를 실행할 수 있습니다. 일반 사용자가 앱을 켜는 데 필요한 단계는 아닙니다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

프런트엔드 로딩 순서 테스트는 Node.js가 이미 있는 개발 환경에서 다음 명령으로 실행합니다.

```powershell
node --test tests/dashboard-loading.test.cjs
```

Python 테스트 47개와 JavaScript 테스트 8개가 있습니다. 기사 저장·승인 테스트는 SQLite 테스트 어댑터를 사용하고, 정부광고 DB와 OpenAI API 호출은 모의 객체·HTTP 전송을 사용합니다. 실제 OpenAI SDK의 요청·응답 처리는 모의 HTTP로 검증합니다. 이 테스트들은 실제 MySQL 접속이나 유료 API가 작성한 기사 품질 검증을 대신하지 않습니다. 일반 사용자에게 Node.js 설치가 필요한 것은 아닙니다.

## 9. 대표 매체군 비교와 OpenAI API 기사 초안

**웹에서 사용하려면 [ARTICLE_WORKFLOW.md](ARTICLE_WORKFLOW.md)를 따릅니다.** 2022~2026년의 기준연도와 비교연도를 하나 또는 여러 개 선택할 수 있습니다. 방향을 구분한 20개 조합을 지원합니다. 2026년이 포함되면 양쪽 모두 광고시작일 9월 30일 이하, 나머지 조합은 각 연도 파일 전체를 사용합니다.

기사는 검토대기로 저장하고, 사람이 근거와 대조해 검수 4항목을 모두 통과한 뒤 승인합니다. 실패 항목이 있으면 보류하며 직접 승인 API를 호출해도 400으로 거절합니다. 원고를 수정하면 이전 승인이 해제되고 재검수가 필요합니다. MySQL에 기사·근거 스냅샷·검수 이력을 저장하고 승인된 기사만 공개 목록에 표시합니다.

아래는 기존 BAT 방식의 기본 설정입니다.

`media_analysis/RUN_ANALYSIS.bat`을 실행하면 기본 설정에서 2024년과 2026년의 국가행정기관·공공기관 자료를 함께 집계합니다. 두 연도 파일에서 광고시작일이 각각 9월 30일 이하인 내역을 추리며, 종이신문(인쇄)·방송·인터넷을 구분해 비교합니다. 시작일 하한이 없어 이전 연도 시작 광고도 포함합니다.

이어서 `media_analysis/WRITE_ARTICLE.bat`을 실행하면 계산된 팩트시트를 OpenAI Responses API에 전달합니다. 기사 작성용 패키지 설치와 `.env`의 `OPENAI_API_KEY` 설정이 필요하며 호출 시 API 사용료가 발생합니다. 기사 초안은 3문단·경어체로 요청하고, 건수와 10% 이상 증감률을 중심으로 설명하며 필요한 금액만 반올림해 표시합니다.

[비교·기사 작성 안내](media_analysis/README.md)에 BAT 방식의 결과 파일, 프롬프트 위치와 분석 조건을 정리했습니다. 웹의 기사·검수 기록은 MySQL, BAT 방식의 결과는 `comparison_output`에 저장하며 Git에는 포함하지 않습니다.

## 10. 본인 수행 부분과 AI 활용

Gemini와 ChatGPT(Codex)의 도움을 받아 코드를 작성·수정했습니다. 아래는 학습자가 직접 정한 분석 기준과 실행·검토 과정입니다.

| 본인 수행 부분 | 구체적인 내용 |
|---|---|
| DB 설정·자료 적재와 실행 | MySQL에 정부광고 자료를 적재하고, VS Code에서 서버를 실행해 화면과 조회 결과 확인 |
| 로딩 문제 확인 | 상세 자료와 상단 요약의 표시 시간을 직접 측정하고, 진단 로그를 확인하며 개선 결과 대조 |
| 분석 대상과 매체군 설정 | 지방정부를 제외한 국가행정기관·공공기관을 분석 대상으로 정하고, 보수·진보 대표 매체군의 선정 범위 지정 |
| 연도·기간 비교 기준 설계 | 2024·2026년 비교에서 시작해 2022~2026년의 연도 조합으로 확대하고, 2026년 포함 여부에 따른 기간 규칙 지정 |
| 매체 유형별 비교 요구 | 종이신문(인쇄)·방송·인터넷을 구분해 비교하고 같은 매체의 유형별 변화도 살펴보도록 요구 |
| 기사 프롬프트 수정 | 건수·증감률 중심, 10% 이상 증감 사례 선별, 필요한 금액의 억 단위 반올림, 분량 축소, 경어체 등 작성 지침 지정 |
| 생성 초안 검토·보완 | 중복 설명과 매체 나열을 줄이고, 금액 증감 설명에 누락된 기준연도 금액을 함께 제시하도록 수정 요청 |

코드 구현·리팩터링·자동 테스트 구성은 AI의 지원을 받았습니다. 자동 테스트의 범위와 실제 환경에서 추가로 확인할 부분은 [8번](#8-개발자용-동작-검증)에 구분했습니다.

현재 웹 실행 순서는 **서버 실행 → 기사 작성·검수 화면 → 비교연도 선택 → 분석 근거 불러오기 → 기사 생성 → 근거 대조·수정 → 검수 결과 저장 → 승인 또는 보류**입니다. 설치와 추가 SQL 실행은 [ARTICLE_WORKFLOW.md](ARTICLE_WORKFLOW.md)를 따릅니다. 기존 BAT 실행 순서는 [media_analysis/README.md](media_analysis/README.md)에 별도로 안내합니다.

## 11. 미구현 항목

- **개별 매체 선택 및 연도별 광고 집행 실적 비교:** 사용자가 특정 매체와 두 연도를 직접 선택해 그 매체의 광고 건수·금액·증감률을 비교하는 전용 기능입니다. 예를 들어 조선일보를 선택한 뒤 2024년과 2025년의 실적을 비교하는 화면은 아직 없습니다. 현재 선정 매체군 분석에 개별 매체의 비교 수치가 포함되는 것과 구분합니다.

## 12. 주요 개발·커밋 기록 요약

- **1차:** FastAPI + MySQL 기반 정부광고 집행내역 조회 앱 구현, 연도·기관·매체별 검색 및 집계 기능 구성
- **2차:** 코드 역할별 분리, 로딩 속도 개선, README와 초보자용 설치·실행 안내 정리
